# Прямые команды сигнального бота

Получатель готовит исполнение только в настроенных PAPER и/или BingX VST.
REAL/mainnet этот канал не включает.

## Активное правило выхода

По указанию владельца от 2026-10-24 PAPER и VST используют полный тейк при
текущей подтверждённой цене не ниже 105% фактической цены входа. Закрывается весь
оставшийся объём, включая остатки прежних частично закрытых позиций.
Разделения 80/20 и самостоятельных частичных тейков в этом режиме нет.

Это +5% движения цены, а не +5% ROE: при плече 10× получается приблизительно
+50% к марже до комиссий, funding и проскальзывания. Исполнение рыночное,
поэтому цена фактического выхода не гарантируется на уровне ровно +5%.
Исторический пик не запускает ретроактивный выход.

Проверенные стопы сохраняются; более ранние явные команды полного закрытия
источника также сохраняют силу. Решение тейка имеет отдельное происхождение
`executor_policy` / `fixed_price_take_profit_5pct` и не выдаётся за команду
сигнального бота. VST по-прежнему требует подтверждения собственных ордеров,
филлов, позиции и очистки стопов; это не включение REAL.

## Массовая очистка по указанию владельца

`POST /api/trading/reset` защищён тем же `X-Trading-Token`, что и команды.
Тело: `{"resetId":"unique-owner-operation-id","confirm":"cancel_queue_and_close_paper_vst"}`.
Повторять нужно с тем же ID. Ответ 202 означает сохранение запроса, не закрытие.
423 означает занятый worker: повторить с тем же ID. 409 означает незавершённую
предыдущую очистку либо отсутствие нужного VST worker.

В одной транзакции под обоими worker-lock сохраняются отмены старых ожидающих
входов и полные закрытия собственных PAPER/VST позиций. Старые ожидающие команды
помечаются superseded. История, филлы и нативные intent не удаляются и не
объявляются исполненными. REAL и посторонние позиции счёта не затрагиваются.
Сигналы старше границы очистки больше не допускаются к входу, включая поздние
повторы. Свежие поступления сохраняются, но ждут подтверждённого окончания
очистки; обычный TTL не продлевается. Работа закрытий и сверок не останавливается.

`GET /api/trading/reset?resetId=...` возвращает фактический прогресс доставок:
`closing`, `needs_review` или `completed`. Отказ или неоднозначность исполнения
не считаются успехом и не снимают приостановку входов.

Для оператора: `node scripts/request-owner-reset.mjs --url <проверенный URL
публикации> --reset-id <тот же ID> --confirm`; для проверки заменить `--confirm`
на `--status`. Секрет используется из окружения и не выводится.
После публикации новый API необходимо вызвать отдельно: один Publish не
запускает массовое закрытие. В preview VST-исполнение отключено.

## Все паттерны

Ограничение четырьмя ID снято на приёме, при создании PAPER-позиции, при
построении VST policy и в обеих VST-проверках входа. `experimental` не запрещает
исполнение. Подтверждение, TTL, LONG/market, исходный защищённый план и проверки
биржи/средств/владения сохраняются. Старые отклонённые сигналы не переигрываются.

## Приём

`POST /api/trading/commands`

Авторизация: `X-Trading-Token`, тот же токен, что у webhook входа.
`Content-Type: application/json`.

```json
{
  "commandId": "cab-close-18097-1",
  "sourceSignalId": "cab-signal-18097",
  "symbol": "GRIFFAINUSDT",
  "type": "close",
  "sequence": 1,
  "occurredAt": "2026-10-12T08:00:00.000Z",
  "reason": "trailing_exit",
  "scope": "all"
}
```

- `commandId`: уникальный неизменный ID события. Повторять **тот же** ID и тело.
- `sourceSignalId`: ID исходного входа; не переиспользовать для новой позиции.
- `symbol`: контракт в формате `ETHUSDT`, без дефиса.
- `sequence`: положительный целый номер события для одного `sourceSignalId`.
  Пропуски номеров разрешены. Источник должен отправлять события по порядку.
- `occurredAt`: время события ISO 8601. Старые доставленные события не отбрасываются
  только из-за возраста: привязка к поколению позиции обязательна.
- `reason`: машинный код, строчные латинские буквы/цифры/`_`/`-`, до 64 символов.
- `close`: только полный выход; `scope` можно опустить, значение по умолчанию `all`.
  Частичные доли пока возвращают 422, никогда не превращаются в полный выход.
- `move_stop`: вместо `scope` обязательно `stopPrice`, **строка** абсолютной цены.
  VST округляет LONG-стоп вверх до точности контракта. Понижение уже подтверждённой
  защиты отклоняется. Пересечённый стоп не превращается в самостоятельный market-close:
  источник должен прислать отдельный `close`.
- `cancel_entry`: без `scope` и `stopPrice`. Отменяет только ещё не исполненный вход.
  Не закрывает позицию. Неопределённая заявка сначала сверяется с биржей.

200 — точный повтор. 202 — надёжно сохранено, **не исполнено**.
409 — изменённое тело для того же ID, повтор номера с другим ID или конфликт инструмента.
422 — неверный/неподдерживаемый формат. 503 — повторить позже с прежним ID.
Для повторной отправки после исправления отклонённой команды нужен новый ID и номер события.

Источник должен сохранять команду в своём outbox **в одной транзакции** с изменением
трекера, повторять POST до надёжного получения и отдельно отслеживать исполнение.
Наш ответ не заменяет transactional outbox на сигнальной стороне.

## Подтверждение исполнения

`GET /api/trading/commands?commandId=cab-close-18097-1`
с тем же заголовком авторизации. Без ID возвращаются до 100 команд, ожидающие — первыми.

В `commands[].deliveries` отдельные статусы для `paper` и `vst`:

- `pending`: сохранено, ожидает действия/проверки; `lastError` и `attempts` объясняют ожидание.
- `executed`: PAPER-действие смоделировано либо VST-результат подтверждён биржей.
- `already_closed`: закрытие уже подтверждено, новый ордер не отправлялся.
- `rejected`: команда не исполнена; причина в `lastError`.
- `superseded`: ожидающая перестановка стопа заменена более новой командой или закрытием.

Закрытие приоритетнее перестановок стопа. Старый stop после close не переоткрывает
позицию. Close/cancel блокирует запоздалый вход с тем же `sourceSignalId`, включая
смену режима. Неопределённые биржевые записи не воспроизводятся вслепую.
Перезапуск между биржевым исполнением и ответом сверяет уже сохранённое намерение/результат.

Статусы доступны владельцу в журнале → «Здоровье бота» → «Команды сигнального бота».
GET-сверка позиций остаётся резервным каналом. Адреса сигнальной стороны, фактические
поля и поддержка частичных фиксаций уточняются после предоставления контракта источника.
